# ایجنت کنترل کامپیوتر از طریق تلگرام (نسخهٔ ماژولار)

اجرا (خط فرمان): `python main.py`  |  اجرای برنامهٔ گرافیکی: `python launcher.py`  |  ساخت نصب‌کننده: `build_installer.bat`
فایل‌های `.env`, `memory.json`, `tasks.json`, `reminders.json` کنار `main.py` ساخته/خوانده می‌شوند (در exe: `%APPDATA%\Agent`).

## ساختار پوشهٔ agentapp

| فایل | مسئولیت | کجا دست بزنم؟ |
|---|---|---|
| `config.py` | همهٔ تنظیمات `.env`، مسیرها، لاگ | تنظیم تازه اضافه می‌کنید |
| `state.py` | وضعیت مشترک (قفل، تاریخچه، پروسه‌ها) و کلاس `Ctx` | |
| `utils.py` | توابع کمکی (JSON، برش متن، مسیر، kill) | |
| `netutil.py` | **شبکه**: پروکسی، TLS 1.2، رله، IP ثابت، ترنسپورت تکه‌تکه، کلاینت AI و Tavily | مشکل اتصال |
| `transport_ptb.py` | ترنسپورت تلگرام روش Bot API (python-telegram-bot) | |
| `transport_telethon.py` | ترنسپورت تلگرام روش **MTProto** (Telethon) — اشیاء هم‌شکل PTB می‌سازد تا هندلرها دست نخورند | مشکل اتصال تلگرام |
| `tools_core.py` | جست‌وجوی وب، تسک‌ها، حافظه | |
| `tools_files.py` | مدیریت فایل، جست‌وجوی فایل، دانلود | |
| `tools_system.py` | دستور سیستم، مرورگر، اسکرین‌شات، پروسه‌ها، خاموشی، کلیپ‌بورد، GUI | ابزار جدید سیستمی |
| `safety.py` | دستورهای مسدود/خطرناک و تایید با دکمه | قوانین امنیتی |
| `reminders.py` | یادآورها و زمان‌بند | |
| `brain.py` | لیست ابزارها برای AI، `HANDLERS`، پرامپت سیستم، حلقهٔ تصمیم‌گیری | **ابزار جدید = اینجا ثبت شود** |
| `handlers.py` | فرمان‌ها و پیام‌های تلگرام (`/status`, `/cmd` ...) | فرمان جدید |
| `app.py` | ساخت برنامه و `main()` | |

## اضافه کردن یک ابزار جدید
1. تابع را در فایل مناسب `tools_*.py` بنویسید.
2. در `brain.py` در لیست `tools` شرحش را اضافه و در `HANDLERS` ثبتش کنید.

پوشهٔ `diagnostics` ابزارهای تست شبکه است (بعد از رفع مشکل لازم نیستند).

## روشن کردن MTProto
در `.env`: `TG_TRANSPORT=mtproto` و `TG_API_ID` و `TG_API_HASH` و `MTPROXY` (یا `TG_SOCKS5`). نصب: `pip install telethon python-socks`.
فایل نشست `agent_mtproto.session` کنار `.env` ساخته می‌شود؛ پیام «آنلاین شد» فقط بعد از اولین پیامی که خودتان به ربات می‌دهید می‌رسد.

## ابزارهای برنامه و پنجره (تازه)
- `control_browser` با `open_app`: مسیر کامل → PATH → میان‌بر Start Menu → `start`؛ وضعیت واقعی را گزارش می‌دهد.
- `execute_system`: `background=true` برای سرور/برنامهٔ گرافیکی (لاگ در `bg_logs`)، پیشوند `powershell:` برای PowerShell، و `start`/`explorer` خودکار پس‌زمینه می‌شوند.
- `window_control` (فقط ویندوز، نیاز به `pip install pywinauto`): list / focus / controls / click / menu / type / read / minimize / maximize / close — برای مدلی که تصویر نمی‌بیند.
- دکمهٔ «اجرا + بقیهٔ کنترل GUI تا ۱۰ دقیقه» در پیام تایید (فقط برای click/type/menu؛ بستن پنجره همیشه تایید می‌خواهد).

## کنترل مستقل با دیدن صفحه (تازه)
- ابزار `see_screen`: مدل تصویر صفحه را (با شبکهٔ مختصات قرمز) می‌بیند؛ تصویر فقط به مدل داده می‌شود نه تلگرام. با `region` می‌تواند ناحیه‌ای را بزرگ‌نمایی کند.
- `gui_control` حالا مختصات را از پیکسل همان تصویر می‌گیرد و خودکار به صفحه تبدیل می‌کند؛ `double_click`, `right_click`, `drag`, `wait` اضافه شد.
- فقط آخرین چند تصویر (`MAX_IMAGES_IN_CONTEXT`) در گفتگو می‌ماند تا هزینه بالا نرود.
- `/auto <شرح کار>`: تا `AUTO_STEPS` مرحله مستقل کار می‌کند. پیام وضعیت زنده در تلگرام ویرایش می‌شود (`PROGRESS`).
- عکسی که با کپشن بفرستید، مدل هم می‌بیند. اگر سرویس تصویر را نپذیرد، خودکار بدون تصویر ادامه می‌دهد؛ برای خاموش کردن کامل `VISION=0`.
- ابزارهای مرتبط فقط مانیتور اصلی را می‌بینند.

## مدل و API
- `OPENAI_BASE_URL` باید به `/v1` ختم شود؛ اگر `/chat/completions` هم نوشته شود خودکار حذف می‌شود.
- `/models` فهرست مدل‌های سرویس، `/model نام` تغییر مدل بدون ریستارت.
- `python diagnostics/test_model.py [مدل]`: فهرست مدل‌ها + تست گفتگو، tool calling و دیدن تصویر.

## پروایدر، کلید و مدل در زمان اجرا (بدون ریستارت)
فایل `providers.json` کنار `.env` ساخته می‌شود (حاوی کلیدها است؛ آن را به کسی ندهید). پروفایل `default` همان `.env` است.

| فرمان | کار |
|---|---|
| `/provider` | فهرست پروفایل‌ها (کلیدها ماسک می‌شوند) |
| `/provider add نام آدرس کلید [مدل]` | افزودن پروایدر؛ پیام حاوی کلید از چت پاک می‌شود |
| `/provider use نام` | فعال کردن |
| `/provider del نام` | حذف |
| `/provider test` | تست گفتگو، tool calling و دیدن تصویر |
| `/key کلید` | تغییر کلید پروفایل فعال |
| `/baseurl آدرس` | تغییر آدرس پروفایل فعال |
| `/model نام` ، `/models` | تغییر مدل / فهرست مدل‌ها |

اگر `OPENAI_API_KEY` در `.env` خالی باشد، ایجنت باز هم بالا می‌آید و با `/key` یا `/provider add` کلید می‌دهید.

## مصرف توکن
- `/usage`: مصرف از شروع برنامه (درخواست‌ها، ورودی/خروجی، cache) و سربار ثابت هر درخواست؛ `/usage reset` صفر می‌کند. `SHOW_USAGE=1` مصرف را زیر هر جواب می‌نویسد.
- پرامپت و توضیح ابزارها پیش‌فرض انگلیسیِ کوتاه است (`PROMPT_LANG=en`)؛ جواب‌ها همچنان فارسی‌اند.
- بخش ثابت پرامپت (قابل cache) جدا از بخش متغیر (زمان و حافظه) است؛ بخش متغیر به پیام آخر کاربر اضافه می‌شود.
- نتیجهٔ ابزارهای قدیمی در یک کار طولانی کوتاه می‌شود (`COMPACT_*`)، تاریخچه و نتیجهٔ ابزارها سقف دارند، تصویر صفحه ۱۰۲۴ پیکسل است.

## برنامهٔ گرافیکی سبک و فایل نصبی

**ساختار:** `launcher.py` نقطهٔ ورود است. `agentgui/` رابط (ترای، پنجرهٔ اصلی، فرم‌های تنظیمات)، `agentapp/settings.py` تعریف و اعتبارسنجی تنظیمات، `agentapp/runner.py` اجرا/توقف ایجنت به‌صورت پردازش جدا، `agentapp/secure_store.py` رمزنگاری.

**رفتار برنامه**
- با ورود به ویندوز در ترای بالا می‌آید (`Agent.exe --tray`)؛ آیکون سبز = در حال اجرا، زرد = راه‌اندازی مجدد، خاکستری = متوقف.
- پنجرهٔ اصلی فقط سه دکمه دارد: **اجرا**، **توقف**، **توقف کامل و خروج**. بستن پنجره (X) آن را در ترای پنهان می‌کند.
- منوی **تنظیمات** هر بخش را در یک فرم جدا باز می‌کند: اطلاعات مهم تلگرام (توکن ربات، API ID، API Hash، آیدی کاربر) | هوش مصنوعی (کلید، آدرس، مدل) | پروکسی و اتصال | رفتار ایجنت | عمومی. «ورود از فایل .env» تنظیمات قدیمی را وارد و فایل متنی را امن‌پاک می‌کند.
- ایجنت خودش یک پردازش جداست؛ خطا یا توقف آن ترای را نمی‌اندازد و در صورت خرابی تا ۵ بار در ۵ دقیقه خودکار دوباره بالا می‌آید.

**امنیت**
- همهٔ تنظیمات در `settings.dat` با **DPAPI ویندوز** رمز می‌شوند (فقط همین کاربر ویندوز روی همین سیستم می‌تواند باز کند). متن ساده‌ای روی دیسک نمی‌ماند و ایجنت اطلاعات را فقط از متغیرهای محیطی همان پردازش می‌گیرد.
- کلیدهای `providers.json` (دستور /provider و /key) هم رمز می‌شوند؛ فایل‌های متنی قدیمی خودکار ارتقا می‌یابند.
- لاگ: چرخش خودکار (۵ مگابایت)، و توکن ربات، کلیدهای `sk-…`، Bearer و secret پروکسی از متن لاگ و traceback پاک می‌شوند.
- فایل نشست MTProto (`agent_mtproto.session`) رمز نمی‌شود؛ در `%APPDATA%\Agent` است. اگر لو رفت، توکن ربات را از BotFather عوض کنید.
- ایجنت فقط به `ALLOWED_USER_ID` جواب می‌دهد و کارهای خطرناک تایید می‌خواهند.

**ساخت نصب‌کننده (روی ویندوز)**
1. پایتون ۳.۱۰+ با تیک Add to PATH و [Inno Setup 6](https://jrsoftware.org/isdl.php) را نصب کنید.
2. `build_installer.bat` را اجرا کنید → `Output\Agent-Setup.exe`.
3. نصب‌کننده بدون دسترسی ادمین نصب می‌کند، گزینهٔ «اجرای خودکار با ویندوز» دارد و هنگام حذف می‌پرسد دادهٔ `%APPDATA%\Agent` هم پاک شود.
4. قبل از ساخت می‌توانید `python diagnostics/test_dpapi.py` را برای اطمینان از رمزنگاری اجرا کنید.

## هر نفر ربات و آیدی خودش
- هر نصب فقط با **ربات خودِ کاربر** (توکن از BotFather) و **آیدی عددی خودش** کار می‌کند؛ بدون این دو برنامه اجرا نمی‌شود و به تلگرام وصل نمی‌شود.
- به هر کاربر دیگری که به آن ربات پیام بدهد فقط یک پیام «⛔ شما دسترسی ندارید» (حداکثر دقیقه‌ای یک بار) داده می‌شود و هیچ دستوری اجرا نمی‌شود؛ دکمه‌های تایید هم برای او بی‌اثر است.
- API ID/Hash می‌تواند بین نصب‌ها مشترک باشد؛ توکن ربات و کلید هوش مصنوعی نه.
- نشست MTProto مخصوص هر کامپیوتر ساخته می‌شود (`agent_mtproto_<شناسه>`)؛ نشست تکراری/باطل خودکار پاک و دوباره ساخته می‌شود.

## رفع باگ‌های اخیر
- **حلقهٔ بی‌پایان ابزار:** یک فراخوانی کاملا یکسان بیشتر از ۳ بار اجرا نمی‌شود؛ بار چهارم مسدود و مدل مجبور می‌شود بدون ابزار جواب بدهد (`tool_choice=none`؛ اگر سرویس نپذیرد، بدون ابزار دوباره درخواست می‌شود). مدلِ لجوج بعد از دو دور متوقف می‌شود.
- **JSON فراخوانی داخل متن:** اگر مدل به‌جای tool call واقعی `{"name": "...", "parameters": {...}}` را در متن بنویسد، اگر نام ابزار شناخته‌شده باشد خودکار اجرا می‌شود.
- **پنجره و برنامهٔ فارسی:** «مدیا پلیر»، «کروم»، «نوت‌پد»… به نام انگلیسی ترجمه می‌شوند؛ تطبیق با نام پردازش هم انجام می‌شود؛ اگر پنجره پیدا نشد، فهرست پنجره‌های باز در خطا می‌آید. `open_app` برنامه‌های فروشگاه ویندوز (Media Player، Telegram Store…) را هم از `Get-StartApps` پیدا و اجرا می‌کند.
- **هشدار pywinauto (STA/COM):** ترتیب import اصلاح شد.
- **کلید API و خطای ۴۰۱/۴۰۳:** کلید از فاصله و کاراکتر نامرئی (RLM/ZWNJ…) پاک می‌شود؛ ۴۰۳ دیگر «کلید اشتباه» گزارش نمی‌شود و متن واقعی سرویس نشان داده می‌شود؛ `AI_USER_AGENT` برای سرویس‌هایی که User-Agent پایتون را می‌بندند؛ `providers.json` با نوشتن اتمیک و cache خوانده می‌شود (قبلاً هم‌زمانی نوشتن/خواندن گاهی به پروفایل پیش‌فرض و کلید پروایدر دیگر برمی‌گشت)؛ جابجایی کلید/مدل در `/provider add` و `/key` و `/model` تشخیص و اصلاح یا رد می‌شود.

## قابلیت‌های الهام‌گرفته از Hermes Agent
- **مهارت‌ها (`skill`):** بعد از کار چندمرحله‌ای موفق می‌توانید بگویید «این را به‌عنوان مهارت ذخیره کن». فایل `skills/<نام>/SKILL.md` (قالب agentskills.io) ساخته می‌شود؛ ذخیره/حذف تایید شما را می‌خواهد و متنی که شبیه توکن/کلید باشد ذخیره نمی‌شود. دفعهٔ بعد مهارت‌های مرتبط با درخواست در پیام ذکر می‌شوند و مدل آن‌ها را `view` می‌کند. `/skills` فهرست را نشان می‌دهد.
- **حافظهٔ جست‌وجوپذیر (`search_memory`):** گفتگوها در SQLite (FTS5) ذخیره می‌شوند (توکن/کلید پاک‌شده، فقط روی همین سیستم). `/forget yes` همه را پاک می‌کند؛ `KEEP_HISTORY=0` خاموشش می‌کند.
- **برنامه‌ریزی (`plan`):** برای کارهای ۳ مرحله‌ای یا بیشتر، چک‌لیست در پیام وضعیت تلگرام نمایش داده می‌شود.
- **مرورگر با DOM (`browser`):** با Playwright روی Chrome/Edge خود ویندوز و پروفایل جدا؛ مدل «شمارهٔ عنصر» می‌بیند (`[3] input «نام»`) نه مختصات. کلیک روی دکمه‌های ثبت/پرداخت/حذف و نوشتن در فیلد رمز/کارت تایید می‌خواهد؛ آدرس‌های محلی و `file://` بسته‌اند؛ کپچا و پرداخت را به شما می‌سپارد. نیاز: `pip install -r requirements-browser.txt` (در نصب‌کننده اختیاری است).
- **Excel/Word (`office`):** خواندن/نوشتن/افزودن ردیف/جایگزینی در `.xlsx` و `.docx` بدون نصب Office؛ پیش از تغییر فایل موجود نسخهٔ `.bak` ساخته و تایید گرفته می‌شود؛ متن فارسی در Word راست‌به‌چپ می‌شود.
- **گروه‌های ابزار تنبل:** `browser` و `office` فقط وقتی به مدل داده می‌شوند که درخواست کلیدواژه‌اش را داشته باشد یا مدل `enable_tools` بزند؛ تا توکن هر درخواست زیاد نشود.

## پنل وب (کنار تلگرام)
**فعال‌سازی:** تنظیمات ← «پنل وب»: فعال‌سازی + یک رمز (حداقل ۱۰ کاراکتر) + (اختیاری) «دسترسی از شبکهٔ خانه». ایجنت را دوباره اجرا کنید؛ آدرس‌ها در «تنظیمات ← آدرس و گواهی پنل وب» نشان داده می‌شوند.
- فقط همین کامپیوتر: `http://127.0.0.1:8787` — بدون هشدار گواهی.
- شبکهٔ خانه: `https://<IP کامپیوتر>:8787` از گوشی/لپ‌تاپ روی همان Wi-Fi. مرورگر هشدار گواهی می‌دهد (گواهی را خود برنامه ساخته)؛ بار اول اثر انگشت را با مقدار نمایش‌داده‌شده در برنامه تطبیق دهید. ویندوز هنگام اولین اجرا فایروال می‌پرسد: فقط **Private networks** را بپذیرید.
- همان ایجنت، همان تایید دکمه‌ای، همان قفل «یک کار در هر زمان»؛ آپلود/دانلود فایل، وضعیت زنده، فهرست دستورها بر اساس کاربرد. با MTProto پنل قبل از اتصال تلگرام بالا می‌آید و با فیلتر بودن تلگرام هم کار می‌کند (در حالت Bot API بعد از اتصال تلگرام).
- **امنیت:** پیش‌فرض خاموش و فقط loopback؛ در حالت شبکه فقط HTTPS و فقط IPهای RFC1918/link-local؛ رمز با SHA-256 و مقایسهٔ زمان‌ثابت، قفل بعد از ۵ تلاش ناموفق، کوکی HttpOnly + SameSite=Strict (+Secure)، توکن CSRF و بررسی Origin، بررسی Host (ضد DNS-rebinding)، CSP با nonce و بدون inline، خروجی HTML پاک‌سازی‌شده، handshake هر اتصال در ترد جدا (اتصال بی‌کار سرور را قفل نمی‌کند)، سقف ۶۴ اتصال، کلید خصوصی گواهی رمز روی دیسک.
- ⚠️ پورت را هرگز روی روتر به اینترنت باز (port-forward) نکنید؛ این پنل در عمل «کنترل کامل کامپیوتر» است.

## شماره‌گذاری مهارت‌ها و تسک‌ها
- هر مهارت یک شمارهٔ دائمی می‌گیرد (`#3`) که با حذف یا ویرایش دیگران عوض نمی‌شود و دوباره استفاده نمی‌شود. بگویید «با مهارت شماره ۳ این کار را بکن» (یا `skill 3`، ارقام فارسی هم)؛ برنامه متن مراحل را خودش قبل از مدل می‌گذارد. `/skills` و `/skills ۳`، ابزار `skill` (view/delete) هم شماره را می‌پذیرند. مهارت‌های قدیمی بدون شماره، اولین بار به ترتیب زمان ساخت شماره می‌گیرند.
- تسک‌ها `#شماره ⬜/✅` نمایش داده می‌شوند؛ «تسک شماره ۳ را انجام بده» متن همان تسک را به مدل می‌دهد؛ `/done ۳` و `/deltask #3` با ارقام فارسی هم کار می‌کنند.
- دستورهای ربات بر اساس کاربرد گروه‌بندی شده‌اند (کارهای اصلی | سیستم و فایل | تسک و یادآور | مهارت و حافظه | هوش مصنوعی و تنظیمات)؛ منوی تلگرام، `/start` و صفحهٔ وب از یک فهرست می‌آیند.
